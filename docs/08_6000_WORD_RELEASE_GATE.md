# 08. 6,000단어 기본 제공 — 출고 게이트 및 검증 시나리오

> 이 문서의 모든 **BLOCKER**를 해소하지 않으면 Codex는 프로젝트를 완료했다고 보고해서는 안 된다.

## 1. 완료의 의미

Wordloom은 **실제 TOEFL 학습에 적합한 영어 표제어와 자연스러운 한국어 뜻이 포함된 6,000개 이상의 고유 단어**를 기본 설치한다.

- 단어가 `data/packs/*.json` 등의 **배포 파일 안에 실제 존재**할 것.
- 사용자 import·수동 다운로드·회원 가입·외부 사전 요청 없이 앱 첫 실행 시 전량 설치할 것.
- 카드, 시험, 단어 검색, 복습에 저장된 전량이 활용 가능할 것.
- 초기 준비가 끝난 뒤 오프라인에서도 전량 학습 가능할 것.
- '6,000' UI 문자열, `expectedCount` 상수, 6,000개 테스트 fixture만으로 충족했다고 주장하지 말 것.

## 2. BLOCKER 체크리스트

| 코드 | 출고 차단 조건 | 증거 |
|---|---|---|
| GATE-01 | 배포 실데이터 유효 고유 영어 표제어가 6,000개 미만 | validator 실제 실행 로그·전체 counts |
| GATE-02 | 한글 뜻 공란, 자리표시자, 무의미한 번역이 존재 | 스키마/휴리스틱 검사 결과, 품질 표본 보고 |
| GATE-03 | 데이터 소스의 권한/라이선스/표시 의무 확인되지 않음 | `data/sources/README.md` |
| GATE-04 | 단어 패키지가 저장소/배포 산출물에 포함되지 않음 | manifest와 실제 배포 파일 비교 |
| GATE-05 | 신규 사용자에게 6,000개를 자동 설치하지 못함 | 깨끗한 프로필 초기 로드 결과 |
| GATE-06 | IndexedDB의 실제 6,000개와 UI 숫자 불일치 | DB 조회 및 홈·단어장 비교 |
| GATE-07 | 오프라인에서 6,000개 중 일부만 사용 가능 | 비행기 모드 검색·카드·퀴즈 |
| GATE-08 | 앱 업데이트 중 기존 진도/오답/즐겨찾기 유실 | v1→신규 데이터 마이그레이션 테스트 |
| GATE-09 | 검증 실패에도 테스트/빌드가 성공으로 종료됨 | 5,999개·빈 뜻·중복·404 부정 시험 |
| GATE-10 | 샘플을 넘어선 앱 기능이나 PWA 설치 흐름 미완성 | E2E/모바일 수락 테스트 |

## 3. 자동 검증 명령의 계약

- 권장 실행: `node scripts/validate-vocabulary.mjs` (다른 구현도 가능).
- 성공 시: 전체 raw count, 중복 제거 후 count, 레벨별/카테고리별 count, 출처 요약, 최종 유효 단어 수를 출력하고 exit 0.
- 실패 시: 원인·문제 파일·항목 ID를 출력하고 exit code non-zero.
- 모든 패키지를 manifest로 탐색할 것. 테스트 fixture는 별도 디렉터리에서 취급.
- **검사 단계**: 누락 파일, JSON 스키마, 필수 필드, normalized lemma 중복, stable ID, 한국어 뜻 존재, placeholders, source 참조, 최종 ≥6,000.
- **내용적 사실성**: 자동 검사로 보장할 수 없으므로 레벨/주제/출처별 표본 QA 및 수정·미확인 사항 리포트를 추가할 것.
- Codex가 구현한 테스트 결과가 없으면 '통과'라고 쓰지 말 것.

## 4. 신규 사용자 관점 수락 시나리오

1. 빈 IndexedDB/Cache Storage 상태에서 앱을 HTTPS/localhost로 열기.
2. 카탈로그 manifest 및 실제 데이터 팩의 다운로드·검증·시딩 완료를 기다리며 진행 상태 확인.
3. `words` store 고유 카운트 ≥6,000과 홈 표시 수치를 비교.
4. 첫/중간/마지막 인덱스, 각 레벨·카테고리의 임의 표제어를 검색하고 뒤집어 한글 뜻 확인.
5. '전체 단어'에서 10문항 시험을 풀고 오답을 복습한 뒤 새로고침하여 데이터 보존 확인.
6. 완전 오프라인 전환 후 앱 재시작 → 6,000개 전량 및 학습 기록 접근 → 시험 재진행.
7. 변경된 카탈로그를 재배포 후 업데이트 → 기존 카드 상태와 오답 유지.

## 5. 제출물 목록

- `data/catalog-manifest.json`
- `data/packs/`에 **실제 6,000개 이상 항목**
- `data/sources/README.md` 및 의무적인 라이선스·표시 파일, 예: KOReader Dicts 영한 사전을 사용했다면 그 아카이브의 `ATTRIBUTION`에 기반한 크레딧/변경 고지
- 단어 중복·스키마·뜻·출처·총량 검증 스크립트와 테스트
- `app.js` 등 7개 페이지를 구동하는 코드
- Service Worker/manifest/PWA 및 데이터 초기화 로직
- 테스트 결과 리포트: 실데이터 카운트/오프라인/기존 진도 보존
- README: 로컬 실행, HTTPS 배포, 데이터 팩 업데이트, 데이터 출처와 검증 명령

## 6. 잘못된 완료 보고 예시

- ❌ `590개로 앱을 완성했고, 나중에 5,410개를 추가할 수 있습니다.`
- ❌ `6,000개 테스트용 단어로 DB를 채웠으니 완료했습니다.`
- ❌ `6,000개 가져오기 버튼을 제공하므로 목표가 달성됐습니다.`
- ❌ `네트워크 연결 시 외부 사전 API에서 뜻을 찾을 수 있습니다.`
- ❌ `화면에는 6,000개라고 표시됩니다.`

## 7. 올바른 완료 보고 예시

```text
- 배포 데이터: 정규화한 고유 표제어 6,xxx개 (실제 검증 결과)
- 영어·한국어 뜻 필드 유효 수: 6,xxx개
- 데이터 파일: data/catalog-manifest.json, data/packs/...
- 출처와 라이선스: data/sources/README.md
- 검증 명령: node scripts/validate-vocabulary.mjs → PASS
- 첫 실행 DB 시딩: 실제 저장된 6,xxx개 확인
- 오프라인: 카드·검색·10문항 시험에서 전체 데이터 접근 확인
- 진행 기록: 데이터 팩 업데이트 후 SRS/오답/북마크 보존
- 제한 사항: (실제 미검증 항목만 기재)
```

**주의:** 위 수치는 예시 표현이며, 문서 작성 시점에 새 6,000개 데이터가 만들어졌다는 뜻은 아니다. Codex가 실제 데이터를 확보·검증·배포한 후에만 실제 수를 기재할 수 있다.
