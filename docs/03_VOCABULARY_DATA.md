# 03. 실제 6,000개 영단어 데이터 사양과 제공 방식

## 릴리스 불변 조건

**실제 어휘 데이터가 6,000개 이상 기본 포함되지 않으면 이번 프로젝트는 완료가 아니다.** 590개짜리 `data/starter.json`은 개발 시작점일 뿐 출시 데이터가 아니다.

- 전체 제공 데이터에서 정규화한 **유효한 영어 표제어 원형 최소 6,000개**를 세어야 한다.
- 모든 항목이 사람이 학습할 수 있는 영어 단어 또는 통상적인 고정 어구이고, **의미가 있는 한국어 뜻**을 포함해야 한다.
- 어휘 전량이 정적 배포 파일에 포함되고 최초 온라인 실행에서 자동으로 로드·저장되어야 한다.
- 첫 방문과 갱신에서 사용자의 JSON/CSV 가져오기나 외부 제3자 API 연결을 요구하지 않는다.
- 6,000개를 충족시키기 위한 더미/자동 번호 붙이기/반복 표제어/활용형만 대량 추가하기를 금지한다.
- 'ETS/TOEFL 공식 6,000단어'로 오해할 표현을 사용하지 않는다. 학술 영어 및 TOEFL 준비용으로 큐레이션한 목록임을 명시한다.

## 콘텐츠 구성 가이드

영어 초급자가 학술 영어까지 단계적으로 배울 수 있도록 권장 구성(제작 목표; 검증된 데이터 확보 상황에 따라 조정 가능):

| 레벨 | 목표 개수 | 예시 범위 |
|---|---:|---|
| L1 | 약 1,000개 | 기초 고빈도 영어, 핵심 동사·형용사, 학습 필수 표현 |
| L2 | 약 1,500개 | 일반 독해와 대학생활·의사소통 어휘 |
| L3 | 약 2,000개 | 학술 논증·사회과학·자연과학 핵심 어휘 |
| L4 | 약 1,500개 | 인문·생물·지구과학·역사·경제 등 주제 심화 어휘 |
| **총계** | **6,000개** | 동일 표제어는 전체에서 1회만 센다 |

TOEFL 관련성은 학술 독해/강의, 주제 다양성, 빈도, 난이도 등 설명 가능한 기준으로 평가한다. 전문 분야에 지나치게 치우친 희귀어로 수량을 채우지 않는다. 위 수량은 내용 구성 목표이지 시험 출제 빈도의 공식 통계가 아니다.

## 필수 데이터 스키마

```json
{
  "id": "w:analyze",
  "word": "analyze",
  "meaning": "분석하다",
  "category": "학술 논증",
  "level": 2,
  "source": "curated-pack-2026",
  "partOfSpeech": "verb",
  "example": "Students analyze evidence from several sources."
}
```

- **필수:** `id`, `word`, `meaning`, `level`, `category`, `source`.
- **선택:** `partOfSpeech`, `example`, `ipa`, `tags`, `sourceUrl`, `license`, `contentVersion`.
- `id`: 영속적으로 유지. 기존 앱의 ID가 있다면 되도록 보존; 새 데이터는 `w:${normalizedLemma}` 권장.
- `word`: 정상적인 영문 표제어. 공백 정리·Unicode NFKC·소문자 비교한 `normalizedLemma`로 고유성 확인.
- `meaning`: 한글이 포함된 문맥상 맞는 뜻(최소 1개). 번역 누락, 영어 단어를 그대로 반복, `TODO`, `미정`, `번역 필요`, `뜻 없음`, 번호 채우기, 난수 문자열 등 불허.
- `level`: 정수 1~4. `category`: 분류명. `source`: `data/sources/README.md`의 출처/제작 기록에 연결되는 식별자.
- 불규칙 과거형, 복수형 등 단순 굴절형만으로 새 단어 개수를 채우지 않는다. 동일 철자 다의어는 하나의 표제어로 세되 뜻을 구분해 병합한다.
- 예문은 선택사항이다. 출처가 불명확한 제3자 문장을 복사하지 않고 직접 작성하거나 권리가 명확한 문장만 포함한다.

## 우선 검토할 구체적인 공개 영한 데이터 원천

Codex는 무작위 단어를 직접 만들어 6,000개를 채우기 전에, 다음 실제 배포 가능한 후보를 **우선 검토**한다.

- **English → Korean — KOReader Dicts**: https://danielgregorini.github.io/koreader-dicts/en/en-ko/
- 다운로드: https://github.com/DanielGregorini/koreader-dicts/releases/latest/download/en-ko.zip
- 배포 페이지 기준 영어 표제어 **25,985개**, 한국어 번역이 있는 항목 100%, **StarDict ZIP 2.5MB**, 데이터 배포 라이선스 **CC BY-SA 4.0**. 해당 설명은 제공 프로젝트의 공개 메타데이터이며 Wordloom의 실제 편입 수량과 다르다.
- 파생 원천은 English Wiktionary 번역 테이블 및 Princeton WordNet 등을 포함하므로, ZIP 내부의 `ATTRIBUTION` 및 각 원천의 라이선스/저작자 표시 요건을 **반드시 직접 확인**한다.
- 다운로드 날짜·원본 아카이브 SHA-256·릴리스 버전·변환 방법을 기록하고, StarDict의 **영어 표제어와 한국어 번역**을 JSON으로 변환해 선정한다.
- **형태 변화형 index 76,501개를 6,000개 표제어로 세면 안 된다.** 고유 headword entry만 후보로 삼아 TOEFL 관련성·난이도·어휘 품질로 재선정한다.
- 이 사전의 25,985개가 모두 TOEFL용이라는 뜻은 아니다. 저빈도 고유명사/부적절한 전문어/부정확한 번역을 걸러 최종 6,000개 이상을 큐레이션한다.
- 최종 앱의 `설정 > 데이터 출처`에 저작자 표시·라이선스 링크·변경 사항 안내를 제공한다. CC BY-SA 조건이 적용되는 **파생 데이터 팩**은 해당 조건에 맞게 배포한다.
- 후보를 내려받지 못하거나 프로젝트가 이용 조건을 변경했다면 보유 수량을 꾸미지 말고 다른 검증된 자료를 찾아 동일한 출고 조건을 맞춘다.

**중요:** 위 공개 원천은 구현 방향을 제시하기 위한 것이다. Codex는 실제 ZIP 내용을 확인한 후 사용 가능한 필드·재배포·변환 결과를 검증해야 한다. 다운로드가 가능하다는 사실만으로 6,000개 완성 조건이 충족되지는 않는다.

## 실제 배포 파일 구조

```text
data/
├─ starter.json                 # 기존 590개: 필요시 병합
├─ catalog-manifest.json        # 배포 단어 패키지 구성표(필수)
├─ packs/
│  ├─ core-01.json
│  ├─ core-02.json
│  ├─ academic-01.json
│  ├─ science-01.json
│  └─ ...                       # 실제 파일명은 구현 선택
└─ sources/
   └─ README.md                # 출처, 버전, 라이선스, 제작·검수 방식
```

`catalog-manifest.json` 예시 (**이 예시는 형식 설명용이며, 실제 counts/경로는 생성된 실파일에 맞춰 기입**):

```json
{
  "schemaVersion": 1,
  "catalogVersion": "2026.10.1",
  "minValidUniqueWords": 6000,
  "packs": [
    {"path": "data/packs/core-01.json", "sourceId": "licensed-source-a"},
    {"path": "data/packs/academic-01.json", "sourceId": "curated-source-b"}
  ]
}
```

`packs`에 선언한 모든 파일은 실제 존재해야 하고, 빌드/런타임은 manifest를 따라 파일을 읽는다. 예시 파일을 그대로 배포해선 안 된다. `starter.json` 병합 시 중복과 ID를 보존하고 로딩 개수를 정확히 계산한다.

## 콘텐츠 획득 및 라이선스 작업 순서

1. **자료 원천 조사:** 공개 사전/언어 데이터/어휘 목록 중 한국어 뜻과 영어 표제어를 얻을 수 있고, 사용·수정·**재배포** 조건이 명확한 자료를 찾는다. 단어 선정에 사용한 빈도 목록의 권리도 확인한다.
2. **증빙:** 출처 명칭, 정확한 URL, 접근일, 버전/커밋, 라이선스 이름/원문 링크, 저작자 표시·동일조건 변경공유 등 의무를 `data/sources/README.md`에 기록한다.
3. **변환:** 필요한 부분만 추출해 `word`/`meaning` 등을 정규화한다. 한글 뜻이 없는 표제어를 무조건 포함하지 않는다.
4. **선정:** TOEFL 학습 관련성 기준으로 후보 선별 및 L1~L4/주제 분류, 중복/굴절형 제거.
5. **검수:** 자동 검증 100% 통과 후 주제·레벨·출처별 층화 표본을 사람이 검수하기 쉽게 별도 보고서로 제공. 자동 번역/LLM 생성 뜻은 검증된 사전 또는 사람 검토 없이 확정 데이터로 취급하지 않는다.
6. **출고:** 6,000개 이상 검증된 데이터 파일 및 라이선스 공지와 출고 검증 결과를 저장소에 포함한다.

제3자의 상업용 TOEFL 단어장이나 한국어 사전의 뜻/예문을 허가 없이 일괄 복제하지 않는다. 어휘 자체를 임의 조합해 의미를 꾸며내지 않는다. 출처를 확인할 수 없으면 **차단 이슈**로 보고하고 완료 판정을 내리지 않는다.

## 데이터 자동 검사: 필수 구현

`node scripts/validate-vocabulary.mjs` 또는 동등한 명령을 제공한다(구현 언어는 자유). **반드시 검사 실패 시 exit code 1 이상 반환**.

1. `catalog-manifest.json` 및 모든 참조 파일 존재/파싱 검증.
2. 전체 패키지 합산 정규화 표제어 수가 **6,000개 이상**인지 검증(데모/fixture 제외).
3. `id`, 정규화 표제어 충돌이 없거나 합병 규칙에 의해 정확히 하나로 정리되었는지 확인.
4. 모든 `meaning`이 유효한 한국어 뜻 후보인지 확인하고, 빈 값/영어 원문만 있음/자리표시자·반복 문자열을 탐지.
5. 필수 필드, 레벨, 분류, 길이, 잘못된 Unicode/문자열, 안전한 렌더링 검증.
6. 모든 항목의 `source`가 출처 기록에 연결되고 재배포 허용 근거와 필요한 attribution이 존재하는지 확인.
7. 기본 로드/퀴즈/검색/백업 대상으로 같은 카탈로그가 사용되는지 통합 테스트.
8. 총량, 레벨별 개수, 범주별 개수, 이상 항목 및 데이터 파일 크기를 읽을 수 있는 QA 리포트 출력.

자동 검사로 영어 뜻의 **의미적 정확성 전체**를 증명할 수는 없다. 출고 전에 수작업 표본 점검과 문제 단어 수정 기록을 남긴다. 거짓된 '품질 검증 완료' 표시는 금지.

## 런타임: 초기 로드, 업데이트, 오프라인

- 최초 온라인 접속 시 manifest → 내장 JSON 팩 전량 다운로드 → 필드/총량 검증 → IndexedDB 트랜잭션 저장 → 완료 표시.
- **6,000개가 전량 준비되지 않았는데 '설치/다운로드 완료' 또는 전체 단어 사용 가능이라고 표시하지 않는다.** 실패 시 재시도할 수 있게 하고 부분 데이터만으로 완성 UI를 오인하게 하지 않는다.
- 두 번째 접속부터는 버전 정보와 실제 저장된 고유 단어 개수 검증 후 변경이 있을 때만 갱신한다.
- 새 데이터 팩 배포 시 `progress`, 북마크, `quizAttempts`, 일별 기록을 보존하고 해당 `word.id`를 안정적으로 유지한다.
- Service Worker/브라우저 저장 용량 정책에 맞게 **내장 원본 팩 캐시 또는 IndexedDB 완료 상태를 검증**해 네트워크 차단 뒤에도 전량 검색·학습 가능해야 한다.
- 시작 화면에는 실제 설치/접근 가능한 표제어 수를 표시한다. 단순 목표 상수 `6000`을 실수량으로 표시하지 않는다.

## 사용자 단어 import·백업 (보조 기능)

사용자 데이터 가져오기는 개인 확장을 위한 선택 기능이다. **기본 6,000개 제공 의무를 대체하지 않는다.**

- 가져오기: JSON 검증/미리보기/중복 해결/명시적 overwrite 확인.
- 백업: `words`, `progress`, `quizAttempts`, 설정과 필요한 메타 데이터를 안전하게 내보내고 복원.
- 복원: 포맷 버전 검사, 복구 전 검증, `병합`/`전체 교체` 확인, 실패 시 기존 데이터 유지.
- 데이터를 추가해 총량이 6,000개를 넘을 경우 `기본 제공 6,000+개`와 `내 단어 X개`를 구분해 표현할 수 있다.
