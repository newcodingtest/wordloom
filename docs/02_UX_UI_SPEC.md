# 02. UI/UX 및 접근성 명세

## 디자인 방향

- 현재 `styles.css`의 **Wordloom** 디자인 토큰과 컴포넌트 스타일을 최대한 유지한다.
- 컬러 기반: 어두운 딥그린 `#192c2a`, 연두 `#b5f1cf`, 밝은 배경 `#f5f7f3`.
- 단정하고 학습에 집중되는 카드 중심 UI. 모바일 1열, 태블릿/PC는 보조 정보 병렬 배열.
- 하단 고정 내비게이션은 모바일 전용. 콘텐츠가 바에 가리지 않게 `env(safe-area-inset-bottom)` 고려.

## 전역 공통

- `#home`, `#cards`, `#quiz`, `#words`, `#review`, `#stats`, `#settings` 해시 라우팅.
- 해시 변경 후 제목/활성 탭/초점 정보를 갱신, 유효하지 않은 해시는 `#home`으로 이동.
- 모든 주요 작업은 클릭 가능한 `<button>`으로 구현. 카드 자체가 뒤집기 버튼 역할이라면 `button` 또는 `role="button"`, `tabindex="0"`, 키보드 핸들러 + `aria-label`.
- 터치 영역 최소 44×44px 권장. 짧은 애니메이션, 운영체제 감속 모션 설정 준수.
- 로딩, 빈 목록, DB 실패, 오프라인 첫 방문, 단어 import 실패 시 안내/재시도 UX 제공.
- 색상 외에 텍스트/아이콘으로 정답·오답 식별. 시각적 대비를 확보.

## 1. 홈 `#home`

- 상단: `오늘도 20개씩, 꾸준히` 같은 짧은 메시지와 학습 CTA.
- 지표: `오늘 신규 N / 목표`, `복습 대기 M`, `암기 완료 K`, `오늘 시험 점수`.
- CTA: `오늘 카드 시작`, `10문제 풀기`, `틀린 단어 복습`.
- 프로그레스: 실제 저장된 `기본 제공 유효 어휘 N개(최소 6,000개)`, `학습한 단어 M개`, `사용자 추가 단어 K개`를 구별한다. 상수 6,000을 실제 보유량으로 오인하게 표시하지 않는다.
- 첫 방문: 필수 내장 팩 6,000개를 자동 로딩하며 진행률과 검증 상태 표시. 로드 실패 또는 N<6,000이면 완료 UI 대신 오류·재시도 안내.

## 2. 카드 `#cards`

```text
[덱 선택: 오늘 | 복습 | 오답 | 즐겨찾기 | 전체]
[현재 3/20]                         [발음] [북마크]
┌────────────────────────────────────────┐
│                analyze                 │   ← 앞면
│            탭하여 뜻 보기             │
└────────────────────────────────────────┘
뒤집으면: 분석하다 / (선택) 예문
[이전] [다시] [어려움] [알겠음] [쉬움] [다음]
```

- 카드 회전 애니메이션은 선택 사항. 애니메이션이 꺼져도 기능은 같아야 한다.
- `스와이프 좌/우`는 보조 편의 기능으로만 고려하고 필수 액션은 항상 화면 버튼으로 제공.
- 앞면과 뒷면의 보조 텍스트/상태를 시각적으로 구분, 키보드 초점이 분실되지 않게 처리.
- 카드 평가를 저장하기 전까지 '암기 완료' 숫자가 증가하지 않는다.
- 새 카드로 이동할 때 회전 상태를 앞면으로 초기화한다.

## 3. 시험 `#quiz`

- 시작: `범위(오늘/오답/전체)`, `10문제`, `4지선다`, `정답 기록` 짧은 안내.
- 시험 중: `3/10` 진행 표시, 표제어/발음, 선택지 A~D, 1회 선택만 허용.
- 정답 선택 뒤: 정답/내 답, 간단 피드백, `다음 문제` 버튼. 퀴즈 중 우발적 새로고침은 재개 또는 명확한 재시작 안내.
- 결과: `8/10`, 점수, 오답 목록(단어+내 답+정답), `오답 카드로 이동`, `다시 도전`.
- 출제 후보 10개 미만: 퀴즈 진행 화면 대신 왜 불가능한지 보여준다.

## 4. 단어장 `#words`

- 검색 상단 고정은 선택. 단어/뜻 양쪽에 문자열 일치 검색.
- 필터: 난이도, 카테고리, 학습 상태, 북마크.
- 결과 건수 및 정렬: 알파벳/난이도/복습 예정.
- 한 페이지 50~100개 또는 가상 스크롤. 총 6,000개를 모두 한 번에 그리지 않는다.
- 행 탭 시 해당 단어 카드로 이동. 행 내부 북마크는 중첩 클릭 방지.

## 5. 복습 `#review`

- 그룹: `기한 도달`, `퀴즈에서 틀림`, `북마크`(북마크는 별도 탭/필터여도 됨).
- 동일 단어가 여러 그룹에 있어도 오늘 복습할 총 단어 수에는 한 번만 포함.
- 빈 화면: `오늘 복습할 단어가 없어요` + 전체/신규 카드 CTA.

## 6. 통계 `#stats`

- 기초 카드: 확인한 단어, 학습 중, 암기 완료, 복습 대기.
- 최근 7일 카드 평가 수를 막대그래프/리스트로 표시. 숫자/요일을 같이 명기.
- 퀴즈 통계: 응시 횟수, 총 문항, 정답률, 최근 결과.
- '학습했다', '완전히 암기했다' 기준을 도움말로 명시.

## 7. 설정 `#settings`

- 일일 신규/복습 목표, 음성 속도, 데이터 import/export.
- 파일 업로드 오류는 단어 수/실패 원인 예시와 함께 표시.
- 복원(병합/교체) 시 **복원 대상 건수**와 실제 변경 예상치를 미리보기.
- 초기화 버튼은 실수 방지를 위해 경고 + 이중 확인.

## 핵심 컴포넌트 사용 규칙

- 탭 네비게이션: 아이콘+텍스트 모두, 현재 위치는 `aria-current="page"`.
- 진행 상태: 시각적 프로그레스 + `(3/10)` 텍스트.
- 발음 버튼: `aria-label="analyze 발음 듣기"`.
- 라이브 결과: `role="status"` 또는 `aria-live="polite"`, 답정너처럼 지나친 알림 금지.
- 다이얼로그: 키보드 닫기/초점 복귀/배경 상호작용 차단.
- 하단 안전 영역과 휴대폰 주소창 높이 변화에 안전한 높이 처리(`100dvh` 사용 가능, fallback 준비).

## 설치와 오프라인 UI

- `앱 설치 안내`를 옵션으로 제공하되 플랫폼마다 브라우저 절차가 다르므로 정형 버튼만 강제하지 않는다.
- iOS에서는 브라우저 공유 메뉴의 '홈 화면에 추가', 설치 지원 브라우저에서는 설치 프롬프트 등을 안내.
- 브라우저에 발음용 음성이 설치되지 않았다면 음성 재생이 작동하지 않을 수 있다고 표시.
- 데이터는 이 기기 브라우저에 저장됨을 알리고 JSON 백업을 권한다.

## 실제 6,000개 카탈로그 로딩 상태 UX

- 최초 접속 중 `기본 영단어 준비 중: N / 총 M개`처럼 진행 상황을 표시(가능한 실제 계측값 사용).
- 데이터 팩 일부 실패 시 이미 6,000개가 준비된 듯 홈 숫자를 고정 표시하지 않는다. 원인과 재시도 제공.
- 최초 설치 완료 후에는 오프라인 상태에서도 기본 제공 전체 어휘를 학습할 수 있음을 명시한다.
