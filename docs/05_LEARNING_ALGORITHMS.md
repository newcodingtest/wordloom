# 05. 학습 알고리즘 명세 (카드 · SRS · 10문제 시험)

> 초기 버전 목표는 알고리즘의 복잡성보다 **예측 가능성, 일관성, 검증 가능성**이다. 개인 맞춤 SRS로 고도화할 여지를 남긴다.

## 1. 카드의 평가와 간격 반복

입력: 기존 progress(없으면 신규), 평가 `again | hard | good | easy`, 현재 시각 `now`. 출력: 새로운 progress. 순수 함수로 테스트 가능하도록 구현.

| 평가 | 첫 평가의 다음 복습 | 기존에 간격이 있을 때 | 암기 상태 |
|---|---|---|---|
| `again` 다시 | 10분 후 | 10분 후로 초기화 | 오답/복습 필요 |
| `hard` 어려움 | 1일 후 | 기존 간격 × 1.2 (최소 1일) | 학습 중 |
| `good` 알겠음 | 3일 후 | 기존 간격 × 2.0 (최소 3일) | 학습 중 |
| `easy` 쉬움 | 7일 후 | 기존 간격 × 2.5 (최소 7일) | 학습 중/암기 |

- 간격은 `intervalDays`에 보관(소수 허용 가능). `again`은 `intervalDays = 10/1440`.
- `again`은 `lapses += 1` 및 `repetitions = 0`. 다른 평가는 `repetitions += 1`. 카드 판정 기준은 퀴즈 정답과 별개.
- `reviewCount`는 매 평가 때 +1, `lastReviewedAt`/`updatedAt` 기록, 처음 평가 시 `firstReviewedAt` 기록.
- `needsReview`는 카드 평가 완료 시 해제(단, `again`은 10분 후 재노출 가능).
- `암기 완료(mastered)` 정의: `repetitions >= 2 && intervalDays >= 7 && dueAt > now && !needsReview`. 재실패 시 상태에서 제외될 수 있다.
- 최초 평가 `easy`라고 바로 모든 통계에서 '암기 완료'로 처리하지 않음(성공 2회 이상 필수).
- `dueAt`은 UTC ISO 저장. 간격 계산은 `now + intervalDays * 24h` 기준(일 단위 운영 가정). 날짜 표시만 현지 시간.
- 빠른 테스트를 위해 `now` 주입. `Date.now()`를 순수 함수 내부에서 직접 호출하지 않는다.

## 2. 오늘 공부할 카드 덱 선정

정렬 우선순위:

1. `needsReview === true` 퀴즈 오답 중복 제거
2. `dueAt <= now` 복습 기한 도달(가장 오래 지난 순)
3. 아직 카드 평가가 없는 신규 단어 (`firstReviewedAt` 없음)

- 기존 학습한 단어가 '오늘 신규'로 다시 집계되지 않게 한다.
- 오늘 신규 제한(기본 20개), 복습 목표(기본 20개). 복습 전체 대기 수와 오늘 제공량은 구분.
- 전체 카드 덱/카테고리/즐겨찾기는 별도 필터를 지원하며 학습 평가 정책은 동일.
- 새 단어는 시작할 때마다 무작위로 뒤섞여 지나치게 다른 목록이 되지 않게 안정적으로 섞거나 일별 seed를 이용.
- `reviewDue`와 `quizWrong`이 겹치면 한 번만 카드로 표시.

## 3. 10문제 시험 출제

`generateQuiz(words, progressById, mode, seed?)`는 테스트 가능한 순수 함수로 작성.

### 규칙

- 문제 수 **정확히 10**, 문제의 정답 표제어는 중복 없어야 한다.
- 각 문제는 한국어 뜻 4개, 단 하나만 정답. 정답 선택지 위치는 편향 없이 섞는다.
- 보기 후보는 동일 회차/허용된 전체 어휘에서 뽑되 동일한 뜻이나 의미상 거의 같은 보기를 중복 배치하지 않도록 한다.
- 값이 `"분석하다; 조사하다"`처럼 복수 뜻이면 `primaryMeaning`을 일관된 규칙(첫 번째 세미콜론 분리 + trim 등)으로 표시할 수 있다. 단, 매우 유사한 정답/오답 보기는 거른다.
- 고유 정답 단어 10개와 구별 가능한 보기가 충분하지 않으면 `insufficient-items` 오류를 반환한다. 반복 보기로 억지 충족하지 않는다.
- 출제 모드: `today`(최근 학습한 카드), `wrong`(퀴즈 오답), `all`(전체 단어). today/wrong 데이터 부족 시 전체 모드로 **자동 변경하지 않고** 사용자 선택을 요청한다.
- 진행 중 버튼 연타로 중복 제출하면 안 된다. 완료한 시험만 기록에 반영.

### 채점 및 상태

- 사용자가 답 하나를 고르면 답 확정, 정오답 피드백 제공, 다음 문제로 전환.
- `correct = answers.filter(x => x.correct).length`; `percent = correct * 10` (10문제 기준).
- 퀴즈에서 틀린 단어: `quizWrongCount += 1`, `needsReview = true`, `updatedAt` 갱신.
- 퀴즈에서 맞춘 단어: 퀴즈 점수로만 반영. **SRS interval/repetitions를 자동 상승시키지 않는다.**
- 오답은 카드에서 평가를 완료하면 `needsReview` 해제. 암기 완료 계산은 카드 평가에만 종속.
- 시험 중 새로고침 복원은 선택이나 이중 통계 반영 방지는 필수(완료 기록 1회만).

## 4. 학습 기록과 일별 통계

- '본 단어': 화면에 앞면을 노출한 고유 단어 수(카운트의 명확한 정의를 문서화).
- '학습한 단어': 카드 평가를 **1회 이상 완료한** 고유 단어 수.
- '오늘 신규 학습': 로컬 날짜 기준 첫 카드 평가가 오늘인 고유 단어 수.
- '오늘 복습': 로컬 날짜 기준 이미 이전에 평가했던 단어를 다시 평가한 횟수(또는 고유 수. UI에 어떤 기준인지 설명).
- '암기 완료': 위 `mastered` 조건 충족.
- '정답률': 완료된 모든 시험의 `sum(correct)/sum(total)`; 총 문항 0이면 `—`.
- '연속 학습일': 날짜별 카드 평가가 1회 이상 또는 완료 시험 1회 이상 있는 날을 활동일로 간주. 24시간 차이로 계산하지 말고 **사용자 로컬 날짜**로 날짜 키 추출.
- 학습 이벤트를 별도로 보관하지 않는 경우 과거 일별 그래프를 복원하기 어렵다. P0에서는 `meta.dailyStats` (로컬 YYYY-MM-DD 키별 counters) 또는 `studyEvents` 저장소를 선택해 날짜별 평가/시험 활동을 잃지 않도록 한다.
- 날짜가 바뀌거나 시간대가 바뀔 때도 통계의 계산 기준과 저장 형식을 명시한다.

## 5. 예시 테스트 케이스

1. 신규 `analyze` + `good` → 3일 후 due, repetitions=1, 미암기.
2. 위 카드 두 번째 `good` → 6일 후 due, repetitions=2이지만 간격 6일이면 미암기.
3. 한 번 더 `good` → 12일 후 due, 암기 완료.
4. 암기 완료 카드 `again` → 10분 후 due, repetitions=0, 미암기.
5. 10문제 8정답 2오답 → 80%, `needsReview=true`인 항목 정확히 2개.
6. 오답 카드 평가 `good` → 해당 단어 `needsReview=false`.
7. 퀴즈에서 맞췄다는 사실만으로 `repetitions` 변화 없음.
8. 복습 대기와 퀴즈 오답 동일 항목은 오늘 덱에 1번만 등장.
9. `insufficient-items`에서 문항 중복 생성 및 잘못된 정답 보기 없음.

## 6,000개 기본 제공 데이터와의 통합 조건

- 신규 카드·전체 단어 시험·검색·복습은 모두 `data/catalog-manifest.json` 기반으로 실제 설치된 **6,000개 이상 고유 표제어**를 공통 데이터 소스로 사용한다.
- 사용자가 임의 JSON을 가져오기 전에도 `전체` 모드에서 10개 시험이 정상 생성되어야 한다.
- 예시 fixture로만 시험을 테스트하지 말고, 실제 배포 데이터에서 레벨·범주별 임의 문항 생성 결과와 중복 정답/보기 충돌을 검사한다.
