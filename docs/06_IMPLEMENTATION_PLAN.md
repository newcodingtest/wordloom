# 06. Codex 구현 순서 및 체크리스트 — 실제 6,000개 필수

- [ ] 기존 프로젝트 구조·자산·`data/starter.json` 실제 개수/중복 조사.

- [ ] 디자인 재사용, 반응형 320px 대응, 로딩/오류/빈 화면 처리.

**DoD:** HTTP 서버로 콘솔 오류 없는 앱 실행과 화면 이동.

## P0-B. 실제 6,000개 콘텐츠 확보 및 팩 생성 — **필수 차단 게이트**

- [ ] 라이선스상 재배포 가능하고 한국어 뜻 신뢰성이 확보된 실제 어휘 출처 조사.
- [ ] URL·버전·라이선스·저작자 표시를 `data/sources/README.md`에 기록.
- [ ] TOEFL 준비용 빈도/학술 분야 기준을 정의하고 기존 590개 + 후보 목록 병합.
- [ ] 원형 표제어 정규화/중복 제거, 자연스러운 한국어 뜻 및 학습 레벨·분류 검증.
- [ ] 실제 JSON 패키지를 `data/packs/*.json`에 저장하고 `data/catalog-manifest.json` 작성.
- [ ] **유효 고유 표제어 최소 6,000개** 확보. 정의 없는 항목, 더미·번호·기계적 파생 중복 제외.

**DoD:** 실제 배포 데이터의 개수 ≥6,000, 뜻/출처/스키마 검사 통과, 팩 파일 및 출처 문서가 저장소에 존재. 단순 6,000개 테스트 fixture 불허.

### 완료 불가 사례

- 590개 앱을 완성하고 나머지는 '추후 가져오기'라고 처리.
- 6,000개 UI 숫자만 노출하고 실데이터는 590개.
- 6,000개 fixture/무의미한 placeholder를 만들어 카운트 검사만 통과.
- 한국어 뜻이 없거나 잘못 번역된 데이터를 의미 확인 없이 등록.
- 검증되지 않은 저작권 자료를 앱에 동봉.
- SW 캐시에 590개만 남아 오프라인에서 6,000개를 학습하지 못함.
