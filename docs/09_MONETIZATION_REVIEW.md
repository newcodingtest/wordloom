# Wordloom 애드센스 수익화 검토

검토일: 2026-10-26. 대상: 현재 저장소의 정적 PWA, 6,500개 영한 어휘, DuckDNS + Mac mini + Docker + Nginx 배포. 이 문서는 구현 상태와 Google 공식 정책을 대조한 사전 검토이며 승인 결과나 수익을 보장하지 않는다. 광고 코드·가짜 게시자 ID·쿠키 배너를 앱에 추가하거나 신청서를 제출한 상태가 아니다.

## 판단

**웹사이트로 수익화를 검토할 수 있지만, 현재 앱 그대로 광고 코드를 넣어 바로 승인·수익을 기대하는 것은 권하지 않는다.** 배포 기술보다 독창적인 학습 콘텐츠, 심사 가능한 공개 페이지, 개인정보 안내, 적절한 광고 위치가 우선이다. 현재의 카드/SRS/시험 기능은 사용자 가치가 있지만, 6,500개 사전 항목이 6,500개의 독창적인 웹페이지를 의미하지는 않는다.

공식 자격 문서는 만 18세 이상, 정책 준수, 독창적이고 유용한 콘텐츠, HTML 수정 권한 등을 요구한다. 이 문서에 일률적인 방문자 수·글 개수 기준은 제시되어 있지 않다. 임의의 '글 30개면 승인', '단어 6,000개면 승인'을 완료 기준으로 두지 않는다. [Google 자격 요건](https://support.google.com/adsense/answer/9724?hl=en)

## 도메인과 배포

Google은 일반 도메인 외에도 Public Suffix List에 등록된 플랫폼 아래의 사이트를 추가 대상으로 안내한다. 실제 목록에는 `duckdns.org`가 있다. 따라서 `your-name.duckdns.org`를 무료 서브도메인이라는 이유만으로 불가능하다고 단정할 근거는 없다. **이는 두 공식 자료를 조합한 등록 가능성 판단이며, 해당 URL의 수락·소유권 확인·심사 승인을 실제 확인한 것은 아니다.** 계정의 Sites 화면에 정확한 호스트를 추가해 확인해야 한다. [사이트 등록 범위](https://support.google.com/adsense/answer/12170421?hl=en), [Public Suffix List](https://publicsuffix.org/list/public_suffix_list.dat)

Nginx나 Mac mini 자체가 애드센스의 불허 사유라는 근거는 찾지 못했다. 대신 외부에서 안정적으로 접속 가능한 HTTPS, 올바른 HTTP 상태, 크롤러 접근이 필요하다. 잠자기·공유기 장애·인증서 만료로 사이트를 읽지 못하면 심사와 광고 제공에 문제가 될 수 있다. [크롤러 문제 해결](https://support.google.com/adsense/answer/2381908?hl=en)

장기적인 서비스 이름·도메인 통제·주소 이동 비용을 고려하면 보유 도메인 사용을 권장한다. 이것은 제품 운영 권고이며 구매 도메인이 무조건 승인에 필수라는 뜻은 아니다. 보유 도메인을 쓰더라도 DuckDNS를 IP 갱신 용도로 두고 DNS를 연결할 수 있다. 최종 도메인은 가능하면 실제 사용자 학습 기록이 쌓이기 전에 정한다. 이 앱의 IndexedDB는 도메인별로 분리된다.

## 현재 코드에서 확인한 상태

| 항목 | 현재 확인 | 판단·필요 조치 |
|---|---|---|
| 콘텐츠 접근 | index.html의 본문은 초기 준비 안내이며, JS가 카탈로그를 저장한 후 본문 렌더링 | 공개 학습 안내·가이드·해설을 별도 정적 HTML URL로 제공하는 방안 권고 |
| 페이지 주소 | #home/#cards/#quiz 등 해시 라우트 | 해시별 화면을 독립된 검색/심사 페이지라고 가정하지 않기 |
| 콘텐츠 고유성 | 공개 사전 기반 뜻 + 카드/SRS/시험 기능 | 직접 작성한 용법·혼동어 비교·해설·학습법을 추가해 가치를 명확히 제시 |
| 개인정보 안내 | 로컬 저장 안내는 있으나 광고용 개인정보처리방침 없음 | 광고 도입 전에 Google/제3자 쿠키·전송 및 선택권 안내 작성 |
| 운영 정보 | 공개 소개·실제 문의처 페이지 없음 | 서비스 목적, 운영 주체, 수정 요청·연락 경로 제공 권고 |
| 라이선스 | CC BY-SA/WordNet 출처 고지 있음 | 광고 도입 후에도 출처·변경·동일조건 공유 유지 |

| 오프라인 | 앱·전체 어휘 캐시, 외부 출처 요청은 SW 대상에서 제외 | 광고 실패가 학습을 막지 않도록 유지. 오프라인 광고 수익을 계산하지 않기 |

정적 페이지 권고는 크롤러가 읽기 쉬운 구조를 위한 판단이다. Google 검색은 JS를 처리할 수 있지만, 모든 봇이 같은 기능을 제공하는 것은 아니다. 검색용 Googlebot과 광고용 크롤러를 동일하게 가정해서는 안 된다. [Google JavaScript 처리 설명](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [애드센스 크롤러](https://support.google.com/adsense/answer/99376?hl=en)

## 콘텐츠와 데이터 권리

Google은 가치가 낮거나 본문 없는 화면 및 추가 가치 없이 복제된 콘텐츠에 대한 광고를 제한한다. 현재 앱이 자동으로 위반이라고 판정할 수는 없지만, 단어·뜻만 반복 표시하는 화면은 검토가 필요하다. 유용한 기능이 있다는 설명에 더해, 사용자가 공개적으로 읽을 수 있는 학습 콘텐츠를 갖추는 방향을 권한다. [Google 게시자 정책](https://support.google.com/adsense/answer/10502938?hl=en)

권장 콘텐츠 예: 단어별 실제 문맥과 직접 쓴 예문, affect/effect 같은 혼동어 비교, 학술 지문의 어휘 해설, SRS 사용법과 학습 계획, 시험 결과에 대한 의미 있는 해설. 사전 내용을 페이지 수만 늘리려고 그대로 6,500개 URL로 복제하거나 검수 없이 생성 문서를 대량 게시하는 접근은 피한다.

CC BY-SA 4.0은 상업적 이용을 허용한다. 광고 수익화 자체를 금지하는 라이선스는 아니다. 출처·라이선스·변경 고지와 파생 데이터 동일조건 공유를 유지하고, 허용된 데이터 재사용을 광고 시청이나 별도 제한으로 막지 않아야 한다. 데이터 팩의 조건과 독립적으로 작성한 앱 코드·글의 권리 범위는 구분해 관리한다. [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)

현재 원본 사전의 민감한 신체/성 관련 표제어도 광고 대상 문맥을 함께 검토할 필요가 있다. 교육적·사전적 용어라는 사실만으로 모든 광고 문맥의 수락을 단정하지 않는다. 공식 TOEFL 목록 또는 ETS의 승인·후원 서비스라고 표시하지 않는다.

## 광고를 어디에 둘 것인가

| 화면 | 권장안 | 이유 |
|---|---|---|
| 공개 학습 가이드·상세 해설 | 본문과 구분한 반응형 광고 1개부터 검토 | 충분한 콘텐츠와 의도적인 읽기 흐름 확보 |
| 홈 | 소개/학습 안내가 충분한 영역에서 제한적으로 검토 | 바로가기만 있는 화면에 광고를 늘리지 않기 |
| 단어 카드·정답 선택 중 | 초기 광고 대상에서 제외 권고 | 반복 터치·카드 이동 버튼과 광고의 오클릭 위험 |
| 결과 화면 | 정답/오답 해설이 충분할 때 하단 검토 | 점수만 표시한 종료 화면은 피하기 |
| 설정·백업·로딩·오류·빈 복습 | 광고 제외 | 작업/오류 안내 중심이며 콘텐츠가 부족함 |
| 오프라인 | 광고 요청·차단 오버레이 없음 | 학습 기능을 네트워크 광고에 종속시키지 않기 |

광고를 버튼·메뉴처럼 보이게 하거나 '광고 클릭으로 응원'을 요청하면 안 된다. 자기 광고를 클릭하거나 노출을 인위적으로 늘리는 것도 금지된다. 자동 광고는 카드·하단 내비게이션과 겹칠 가능성을 먼저 확인해야 하므로, 초기에는 배치 통제가 가능한 방식이 낫다는 제품 판단이다. [AdSense 프로그램 정책](https://support.google.com/adsense/answer/48182?hl=en)

현재 render()는 카드 반전과 이동 때 main 전체를 다시 만든다. 따라서 main 안에 광고를 무작정 넣으면 광고 DOM을 반복 생성할 수 있다. 광고 슬롯의 수명과 화면별 제외 규칙을 따로 설계하고, 다음 카드/뒤집기마다 광고를 새로 요청하는 코드를 작성하지 않는다. 사용자 카드 조작을 자동으로 광고 새로고침 요청이라고 해석하지 않는다. 사용자 요청 없는 자동 새로고침은 금지되며, 시간 제한 광고를 보여준 뒤 학습을 해금하는 방식도 이 프로젝트에 적합하지 않다. [광고 배치·자동 새로고침 정책](https://support.google.com/adsense/answer/1346295?hl=en)

검토 범위는 HTTPS 웹사이트의 AdSense이다. 홈 화면 PWA 설치를 네이티브 앱용 AdMob 전환으로 취급하지 않는다. 추후 WebView/TWA로 별도 앱을 배포한다면 해당 지원 방식과 정책을 별도로 확인한다. [웹 콘텐츠 프레임 정책](https://support.google.com/adsense/answer/48182?hl=en)

## 개인정보와 동의

Google은 광고에 사용하는 Google/제3자 쿠키, 개인 맞춤 광고, 사용자 선택권 등을 개인정보처리방침에 고지하도록 안내한다. 운영자 연락처·실제 사용하는 광고/분석 서비스·데이터 보관과 선택 경로를 기준으로 작성해야 하며, 현재 상태에서 '어떤 데이터도 외부 전송하지 않음'이라는 문구를 광고 도입 후 그대로 유지하면 부정확하다. 학습 진도를 로컬에 저장하는 것과 광고 요청에서 외부 데이터 처리가 발생하는 것은 별개다. [필수 개인정보 고지](https://support.google.com/adsense/answer/1348695?hl=en)

EEA/영국/스위스 사용자에게 광고를 제공하는 경우 Google 인증 CMP/TCF 요구를 확인해 적용한다. 한국어 서비스라도 해외 접속이 가능하다. 직접 만든 '동의' 버튼만으로 Google 인증 CMP 요건을 충족했다고 보지 않는다. 국가별 실제 운영 조건에 맞는 개인정보 절차는 구현 전에 정해야 한다. [Google CMP 요건](https://support.google.com/adsense/answer/13554020?hl=en)

## 신청과 적용 순서

1. 최종 도메인·HTTPS·24시간 운영을 먼저 확인한다. Nginx 배포 가이드는 deploy/MAC_MINI_DOCKER_DEPLOY.md 참조.
2. 공개 소개·문의·개인정보 페이지와 직접 작성·검수한 학습 콘텐츠를 만든다. 소개/문의는 운영 권고이고, 개인정보 고지 의무와 동일한 근거로 묶지 않는다.
3. 광고 대상 URL을 로그인/개인 IndexedDB 데이터 없이 읽을 수 있게 한다. robots.txt로 광고 크롤러나 필수 JS/콘텐츠를 막지 않는지 점검한다. sitemap/canonical은 검색 관점에서 필요한 경우 추가한다.
4. 본인 계정의 Sites에 도메인을 추가하고, 제시되는 메타 태그/광고 코드/ads.txt 중 지원되는 방법으로 소유권을 확인한다. 사이트가 Ready로 승인된 후 광고를 제공한다. [소유권 확인·사이트 심사](https://support.google.com/adsense/answer/12131223?hl=en)
5. 실제 게시자 ID를 받은 뒤 Google이 제공하는 내용을 루트 `/ads.txt`에 배포한다. ads.txt는 Google 문서상 권장이며 일률적인 신청 필수 조건이라고 단정하지 않는다. 이 저장소에는 가짜 ID를 가진 ads.txt를 생성하지 않았다. 현재 Nginx는 파일이 없으면 404를 반환한다. 향후 파일을 추가할 때 build-release.py와 Docker 빌드의 허용 파일 목록에도 포함해야 한다. [ads.txt 가이드](https://support.google.com/adsense/answer/12171612?hl=en)
6. 화면별 광고 제외, CMP, 레이아웃 공간, 광고 차단/네트워크 실패 시 학습 지속, SW가 광고 응답을 캐시하지 않는지 확인한 뒤 소수의 광고부터 적용한다.
7. 실제 트래픽·이탈·학습 완료율·정책 센터·페이지 RPM을 확인한다. 게시자 본인의 광고 클릭 및 반복 자동 노출 테스트는 하지 않는다.

## 수익성 판단

지금은 실사용자·광고 대상 페이지뷰·국가별 구성·실제 RPM 자료가 없어 수익을 예측할 근거가 없다. 단어가 6,500개이거나 하루에 카드 100번을 넘긴다는 숫자를 광고 수입으로 환산할 수 없다. 오프라인 학습·광고 차단·동의 상태·광고 미게재도 영향을 준다.

계산은 `월 애드센스 집계 페이지뷰 ÷ 1,000 × 실제 페이지 RPM`을 기준으로 한다. [Google 페이지 RPM 정의](https://support.google.com/adsense/answer/112030?hl=en)

아래는 **시장 평균이나 예상 수익이 아닌 가정값의 민감도 계산**이다. 원화 RPM을 가정했으며 비용·세금 차감 전이다.

| 월 광고 페이지뷰 가정 | RPM 1,000원 가정 | RPM 3,000원 가정 | RPM 5,000원 가정 |
|---:|---:|---:|---:|
| 30,000 | 30,000원 | 90,000원 | 150,000원 |
| 100,000 | 100,000원 | 300,000원 | 500,000원 |
| 300,000 | 300,000원 | 900,000원 | 1,500,000원 |

순수익 검토에는 맥미니 실제 소비전력·운영 시간·회선·도메인·유지보수 비용을 반영한다. 이미 맥미니를 보유했더라도 작은 트래픽에서 의미 있는 수익이 자동으로 발생하는 것은 아니다. 초기에는 광고 수를 늘리는 것보다 재방문할 만한 학습 콘텐츠와 검색 유입을 확보하는 편이 합리적이라는 판단이다.

## 현재 결정

Nginx 배포 파일은 준비했지만 실제 Mac/공개 도메인 발급은 아직 실행하지 않았다. 애드센스 사이트 등록·승인·광고 송출·수익 실측도 실행하지 않았다. 권장 다음 구현 범위는 **공개 학습 콘텐츠 + 실제 운영 정보/개인정보 페이지 + 광고를 넣을 화면 선정**이다. 광고 코드는 실제 계정 값과 동의 구조가 준비된 후 적용한다.
